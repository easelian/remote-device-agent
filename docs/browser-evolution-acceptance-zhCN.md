# 浏览器后续能力验收指南

本指南用于执行[后续规划](browser-evolution-plan-zhCN.md)中的 D4 收尾及 D5–D8 扩展验收。现有 BC-01～40 和量化门槛继续由[后端验收指标](browser-backend-acceptance-zhCN.md)定义；本文新增 EX 场景，不删除或重新解释原断言。D5–D8 的接口和测试入口尚未实现，表中的新增路径是实施落点，不是当前可运行用例。

## 1. 先确定验收对象

每次记录独立的组合：Agent 与 Server 源码提交、干净工作树、构建选项、编译器/release profile、二进制 SHA-256、浏览器产品/版本/摘要、OS/CPU、观察 profile、本地策略、扩展版本及客户端版本。复用未改动的服务二进制时，记录其源码来源，并证明受影响的运行时代码与候选一致。切换候选、浏览器、构建选项或协议参数后建立新记录，不拼接旧样本。

判定使用 `passed`、`failed`、`unsupported_correctly_refused`、`not_run`、`not_applicable`。缺环境、跳过或没有执行到预期拒绝点都不能记为通过。必要用例的 JUnit 必须与事先收集的 ID 一一对应，失败、错误和跳过均为零。预期的拒绝是带断言的通过用例，报告中另列拒绝的功能及边界。

不同证据分别回答不同问题：

| 证据 | 可以证明 | 不能替代 |
| --- | --- | --- |
| Fake 与可控 pipe/WebSocket | 状态转移、取消、乱序、容量和所有权 | 浏览器实际执行 |
| 原生 Agent 场景 | 对固定浏览器的观察、输入、身份和进程行为 | Core/MCP 的认证、计量和结果披露 |
| 隔离 Server/MCP 场景 | 从公开工具到真实 Agent、浏览器及人工页面的路径 | 真实 AI 宿主的渲染、缓存与工具选择 |
| 原生平台运行 | 该 OS/CPU 的真实操作和隔离 | 其他平台、浏览器品牌或版本 |
| 八目标构建 CI | 声明目标的构建及相应检查 | 八种原生浏览器运行结果 |

## 2. D4 发布收尾

发布清单只列已经实际验证的组合。v1 与 v2 分列：保留已发布 v1 的支持范围，v2 不因使用同一二进制就继承它的平台声明。首批 v2 可以只声明完成验收的 Linux x86_64 组合；其他组合明确不可用或未验收。

| 收尾项 | 所需证据与放行条件 |
| --- | --- |
| CDP 事件通道 | 完成 D4-R1/EX-00 的聚合字节核算和入队侧停止；不得以 BiDi 队列或已有功能测试结果替代 |
| 候选固定 | 同一组源码、Agent/Server/browser 摘要；开发构建与 release 构建分别标识；不能用旧二进制结果替代当前候选 |
| 完整本地矩阵 | contracts、v1、v2、budgets、recovery、linux-tls、rss 均执行，零遗漏/错误/失败/跳过；历史 Python wire 夹具与原生用例分别识别 |
| 性能与 RSS | 原始样本、资源限制、测量协议摘要、基线稳定性及汇总重算一致；满足原门槛 |
| 真实 AI 客户端 | 对每个要声明的客户端验证设备发现、工具 schema、截图实际渲染、人工接管/交还、文件页面和错误恢复；CLI 通过不能替代现有客户端会话的工具状态 |
| 平台及浏览器 | 精确版本和原生运行结果；最低版本、Firefox ESR 或其他 Chromium 品牌没有证据时不作支持承诺 |
| 托管 CI | 在安排执行后记录固定提交对应的 Server 流程和八目标 Agent 检查结果；尚未执行时保持 `not_run` |
| 版本迁移/回退 | 新旧 Agent/Core、默认构建、v1 资料保持、旧程序拒绝新格式，以及 Core/SQL 函数契约切换；仅处置夹具自行创建的合成数据 |
| 收尾 | 所属进程、原生租约和独立测试服务按预期退出；未确定清理保留 CleanupPending；无生产配置或服务变化 |

本地 TLS 在回环地址执行时标明单机范围。跨主机 TLS、真实客户端和远端设备必须另存证据。本规划本身不启动托管 CI、推送、合并或部署；这些项目未安排执行时，不妨碍独立开发分支上的文档与本地验证，但阻止相应发布声明。

**EX-00：CDP 事件预算与源头停止。** 用可控 pipe 固定事件消费停顿，在 256 条及新增聚合字节预算恰好上限、超一项时检查占用与下一输入。关键消费者尚未 recv 时，超限/缺失/退出判定已经关闭新命令准入，原生端点不能收到下一条输入；已提交命令保留 unknown 及资源所有权，迟到响应只结算原工作。覆盖多个消费者持有同一事件、序列缺口、启动订阅顺序、超大单消息、意外对象事件、弹窗和附件。记录编码字节、结构/副本占用、RSS 峰值和关闭归零；8 MiB 聚合预算是拟实施值，须在实现前固定，现有 2 MiB 单消息和 256 条上限不得增加。拟扩展 `src/browser/engine/cdp/wire/bounds_tests.rs`、`submission_tests.rs` 及真实 v1/共同语义用例。

## 3. D5 只读诊断

为每个场景同时记录诊断结果、调用前后页面状态、原生命令种类、输入/导航/网络计数、控制代次及资源计数。CDP、BiDi 和 Fake 采用同一原因与状态 oracle；原生协议细节单独记录，不按后端忽略公共差异。

| ID | 场景 | 必须满足的断言 |
| --- | --- | --- |
| EX-01 | 稳定可见控件、禁用、只读、隐藏、遮挡、错误动作种类、敏感输入 | 有效 ref 的 status/reason 与冻结语料一致；禁用/隐藏目标保持无动作 ref，观察后失去资格仍返回既有 stale 错误；不返回敏感值、DOM 路径或原生 ID，不改变旧错误目录 |
| EX-02 | 目标在视口外、嵌套 frame、移动布局、旋转/透视 | 只读检查不滚动、不聚焦；不能证明的几何为 indeterminate/明确拒绝，不能误报 ready_now |
| EX-03 | 旧 ref、同名节点替换、记录变化、同 URL reload、BFCache、realm/frame 替换 | 旧身份按现有错误拒绝；没有按名称或选择器重匹配，也不签发替代 ref |
| EX-04 | 提交前后人工接管、调用取消、期限到达、迟到原生响应 | 控制 fence 可推进；结果不能越过披露边界；原生命令和租约到真正结算才释放 |
| EX-05 | 连续检查与随后真实动作 | 检查不续期引用、不产生输入/滚动/导航/表单事件、不消耗上传授权；真实动作仍重新校验并仅按既有流程提交 |
| EX-06 | 结果、原因数和期限恰好达到上限及超一项 | 受限结果或明确拒绝；没有无界等待、额外扫描或占用人工控制通路 |

`ready_now` 只对已检查前置条件负责。诊断后主动改变页面，再发真实动作，必须由动作自身发现变化；这验证诊断不会成为绕过动作校验的许可。参数值合法性、上传一次性授权和站点业务结果另由原动作场景验证。

拟新增 Agent `src/browser/semantic/tests/diagnostics.rs`，覆盖纯判定和可控时序；在既有双后端原生测试中复用同一语料。拟新增 Server `tests/core/test_browser_diagnostics.py`，从公开 MCP 验证主体、能力、计量、错误及人工 fence。新增场景完成前不改变已有套件的预期数量或断言。

## 4. D6 能力指引

| ID | 场景 | 必须满足的断言 |
| --- | --- | --- |
| EX-07 | 旧 Agent、默认构建、v2 关闭、单后端可用、可选文件能力关闭 | 只给当前可执行的示例；不猜测能力，不自动选其他后端，不引导使用任意路径 |
| EX-08 | 不同用户/设备、Agent 重连、会话关闭或能力变化 | 不串用缓存模板参数；每次读取重新授权；旧指引不能改变下一次调用的能力检查 |
| EX-09 | open、observe、recover、handoff、files 全部模板 | 参数通过对应工具 schema；在匹配的真实组合执行；恢复不重放，交还要求披露，文件依赖人工授权 |
| EX-10 | 未知主题、未知模板版本、16 KiB 边界、页面注入文本 | 明确拒绝或有界返回；不把页面内容放进受信任指令模板；不加载外部操作说明 |

模板校验应检查工具名、必需字段、枚举、权限前提与响应中实际存在的字段。仅 JSON 能解析不算示例验收。纯指引读取还须证明没有创建会话或采集页面正文。

## 5. D7 增量观察

### 5.1 正确性与失效矩阵

测试从同一次已授权采集生成完整 oracle 和增量结果，避免用第二次观察的随机 ref 或页面变化掩盖差异。reducer 重建后逐字段比较内容、顺序、覆盖信息、当前 ref/frame 绑定及页元数据；不能只比较 role/name 或文本长度。

| ID | 场景 | 必须满足的断言 |
| --- | --- | --- |
| EX-11 | 初次读取、静态页、单点变化、增删/排序、表单状态、记录结构、名称质量、Unicode | full/delta/unchanged 重建与完整 oracle 一致，零丢失、零额外节点；changed/coverage 保持真实含义 |
| EX-12 | 内容相同但 ref/frame_id 更新；节点从可执行变为不可执行 | unchanged 仍带全部新绑定；旧 ref/frame_id 被拒绝；删除的绑定不残留；展示索引不能执行动作 |
| EX-13 | 同 URL reload、BFCache、realm/frame 替换、查询/范围/预算变化、控制权与策略变化 | 基线失效；授权仍有效时返回新鲜 full，授权无效时原错误；不靠 URL 相等复用 |
| EX-14 | next_cursor、扫描截断、读取中变化、记录资源限制、超缓存大小 | 不建立不完整基线；不隐式继续扫描；原观察预算与拒绝路径不变 |
| EX-15 | 错误/缺失/淘汰/到期基线、其他主体 revision、响应丢失、请求取消、乱序 full/delta、序号耗尽 | 不跨主体查找；受限 full 或明确拒绝；客户端拒绝旧序号/错误 base；失效代次不能被迟到结果重新发布 |
| EX-16 | 并发接管、关闭、失联、恢复后观察 | 内容缓存不可绕过披露；缓存不包含原生对象或输入许可；未知动作继续按原回执处理 |
| EX-17 | 每个缓存/索引/字节上限及超一项；10,000 次观察替换/淘汰/失效 | 实际占用有界；close 后缓存计数归零；普通/释放槽及原生对象预算不变；失败清理不伪造归零 |
| EX-18 | 不支持 reducer 的客户端、MCP 文本与结构化双输出、真实宿主重连 | 默认完整观察；启用增量的接收端能确定性重建并替换全部绑定；重连后重新建立基线；实际展示内容符合当前结果 |

EX-11 的公共 oracle 不接受按 backend kind 的忽略规则。至少覆盖空结果、一个节点、默认 200 项、上限 1,000 项、多个 frame、NBSP/组合字符/非 BMP、可变值和敏感字段。敏感值必须在投影与缓存之前被排除，不能只在最终显示时遮盖。

### 5.2 输出收益与原性能门槛

在实现前固定收益语料：至少 20 个确定性序列，覆盖表单、表格/列表、混合文本、Unicode 和多 frame；每序列先建立一次完整基线，再执行 20 次更新。可缓存的稀疏变化组每次变化不超过 5% 的节点，另设大变化、不可缓存和频繁失效组。所有组都保留原始结果，不事后挑选高收益页面。

| 指标 | 判定 |
| --- | --- |
| 重建正确性 | 同次完整 oracle 与 reducer 结果逐字段一致；任何差异均阻断放行 |
| 单次选择 | 输出 delta/unchanged 时，完整响应字节数 ≤ 同次 full 的 70%；否则 full |
| 可缓存稀疏组总收益 | 计入首次 full、新绑定、元数据及 MCP 双输出后，总字节数 ≤ 同组始终 full 的 70%；防止“始终返回 full”获得空洞通过 |
| 大变化/失效组 | 正确返回 full/拒绝，无额外页面输入或无限重采集；报告 full 比例和原因，不混入稀疏组提高或稀释收益 |
| 原生开销 | 记录命令数量、观察 p50/p95、缓存构造/比较时间；不得通过省略观察或身份检查获取收益 |
| 模型上下文 | 有确定 tokenizer/客户端时另存版本与 token 数；没有时只报告字节，不把字节比例称作 token 节省比例 |

原有门槛完整保留：CDP 配对 p50 增量 ≤ max(基线 10%, 5 ms)、p95 增量 ≤ max(基线 15%, 10 ms)；原生命令 p95 ≤ 基线 120%；控制 fence p99 ≤ 100 ms；Firefox 受限启动/观察/输入 p95 分别 ≤ 10/3/1 秒；Agent 与浏览器 RSS 增长各 ≤ 16 MiB，后端空闲开销 ≤ 8 MiB；剥离后二进制增量 ≤ max(基线 15%, 2 MiB)，新增外部运行时包为零。测量方法和基线稳定性仍以原验收文档为准。

原四组 RSS 测量继续完整执行。D7 另固定“缓存关闭/开启”的对照，覆盖缓存满载、反复失效、并发会话和 100 次关闭循环，记录序列化字节、索引容量、构造副本、实际 RSS/PSS；不能用未填满缓存的 RSS 代替容量验收。新对照的 fixture、参数和摘要在首个样本前固定，不混入原协议的四组样本。

拟新增 Agent `src/browser/semantic/tests/presentation.rs` 和 Server `tests/core/test_browser_observation_delta.py`，并提供接收端 reducer 的共用语料。若没有能运行 reducer 的真实客户端/受控适配器，EX-18 保持 `not_run`，不向该客户端启用增量。

## 6. 跨版本与回退组合

| Core / Agent / 客户端 | 期望 |
| --- | --- |
| 新 Core / 新 Agent / 旧客户端 | 无新增参数时保持旧格式、默认后端、文案和回执；额外工具不改变旧调用 |
| 新 Core / 旧 Agent / 新客户端 | 工具和设备能力联合判断；不支持的扩展在页面工作前拒绝，原有完整观察仍可用 |
| 旧 Core / 新 Agent / 新客户端 | 先按旧工具 schema 使用已支持请求；未知新工具/参数的拒绝边界单列，不能假设旧 Core 会转发 |
| 新 Core / 新 Agent / 扩展关闭或版本未知 | 未声明的扩展不可执行；不自动更换 profile/后端；旧路径继续通过 |
| 新 Core / 新 Agent / 两个主体或两个会话 | 基线、引用、指引与诊断互不泄露；错误 revision 不揭示另一主体是否命中 |
| 回退或重启 | 客户端丢弃展示基线，重新发现能力并完整观察；v1 资料、文件和回执维持原回退规则 |

新增检查必须进入历史 wire、原生 MCP、Core/Runtime 结算及错误目录一致性检查；没有变更操作摘要需求时，不新增 SQL 字段。旧错误文案逐项与固定旧版本比较，新错误仅允许显式追加并覆盖各读取端。

## 7. 执行顺序与现有入口

先执行契约/纯函数与可控传输测试，再执行两个真实浏览器的受影响场景，最后执行完整本地 Server/MCP、重复恢复、独立性能比较和 RSS。只改文档时验证引用、结构和示例；不把规划中的新用例伪报成已运行，也不为文档改动启动整套原生压力测试。

现有 Server 仓库入口为 `scripts/run_browser_acceptance.py`。以下命令用于后续执行已有阶段，不包含尚未实现的 D5–D7 用例。先准备专用 PostgreSQL 和最小权限测试配置，配置文件包含实际的 `RDH_TEST_*` 可执行路径、Node、authority probe、浏览器和旧版本兼容产物；不得指向生产数据库。缺项造成 skip 时必须补齐环境，不能删掉用例。

在 Server 仓库根目录、已配置本项目测试依赖的 Python 环境中执行；`python3` 必须指向含 pytest 及本仓库测试依赖的解释器。先将两个变量替换为私有环境 JSON 的实际绝对路径和一个尚不存在的证据目录：

```sh
set -eu
RDH_ACCEPT_ENV=/private/fixture-environment.json
RDH_ACCEPT_OUT=/private/browser-acceptance-new
test -f "$RDH_ACCEPT_ENV"
test ! -e "$RDH_ACCEPT_OUT"
mkdir -m 700 "$RDH_ACCEPT_OUT"
for phase in contracts v1 v2 budgets recovery linux-tls; do
  python3 scripts/run_browser_acceptance.py --phase "$phase" \
    --env-json "$RDH_ACCEPT_ENV" --output "$RDH_ACCEPT_OUT/$phase"
done
```

`linux-tls` 要求配置中明确的 `RDH_TEST_BROWSER_LAN_HOST`。RSS 另在冻结协议规定的两 CPU、2 CPU 配额、4 GiB、无 swap 的 cgroup 中执行；先固定可用 CPU 编号并同步到协议，不能照抄另一台主机的编号。以下是已进入正确 cgroup 后的现有命令，路径仍需替换：

```sh
python3 scripts/run_browser_acceptance.py --phase rss \
  --env-json /private/fixture-environment.json \
  --output /private/browser-acceptance-new/rss \
  --rss-protocol /private/frozen-browser-rss-protocol.json
```

期望每阶段生成 `acceptance-start.json`、`collected.json`、JUnit、日志和 `acceptance-complete.json`，状态为 passed 且退出码为零。RSS 还生成测量前后协议清单、四组原始样本和汇总。性能使用 Agent 的 release harness 与 `scripts/browser-d1-report.py`，报告与功能测试分开。新阶段实现时扩展收集入口并增加其自身的校验测试，不能靠手工挑选少量用例称作完整阶段验收。

## 8. 证据、失败处理与停止条件

每项 EX 记录预期/实际、通过/失败/拒绝/未运行状态、源码与产物摘要、fixture 版本、请求和输入计数、资源峰值、清理结果及证据路径。公开报告只保留合成数据；失败上下文中的临时凭据在导出时脱敏，记录原文件与导出文件摘要，原始证据在私有位置保留。

校验器须检查：收集 ID 与 JUnit 完全对应，二进制和协议前后未变，样本顺序/数量完整，重算结果与汇总一致；缓存计数、原生租约、pending、任务、进程和目录分别核对。总体通过数不能掩盖某个未运行的平台、客户端或扩展。

发生失败时保存第一次失败及可复现条件，定位到身份、授权、准入、原生执行、结果披露或清理中的具体边界；修复使用独立提交并重跑受影响路径，再判断是否需要完整矩阵。测量环境漂移记 `not_run` 并建立新一轮证据，不能改门槛或删除失败样本。

出现旧引用重新生效、输入重放、主体/控制越界、敏感内容泄露、核心事件丢失后继续输入、未结算工作提前释放、未知清理伪报成功，立即停止该能力放行。收益不足只阻止相应优化公开，不削弱原完整观察功能。

## 9. D8 检查扩展的验收入口

D8 在编码前先补齐独立扩展契约及数值预算。以下是必须细化的验收范围，尚不是已可执行的套件：

| ID | 场景 | 放行条件 |
| --- | --- | --- |
| EX-19 | 原生 AX、深层/超量树、敏感字段、后端字段差异 | 独立版本化结果，节点/深度/字节有界；不覆盖 canonical 字段、不签发动作 ref；不支持的组合明确拒绝 |
| EX-20 | console/网络事件洪峰、携带原生对象的事件、慢消费者、暂停和订阅取消 | 原生对象纳入既有租约；诊断记录可丢失时明确 gap/count，关键事件丢失仍停止；普通控制和清理通路可推进 |
| EX-21 | 认证请求、POST、一次性响应、附件下载与诊断同时启用 | 不重发请求，不改变既有导航/下载决策；默认摘要不含正文、凭据和 URL 查询串；合成服务请求/输入计数与不开诊断时一致 |
| EX-22 | trace 达时间/字节上限、停止、取消、Agent 丢失、人工制品交付、旧程序读取 | 有界停止并结算原生流；制品私有且按类型授权；模型无自动正文披露；资源归零或真实 CleanupPending；旧程序拒绝未知格式并保留数据 |

对每个分段分别运行公开 MCP、权限/计量、v1 共存、真实客户端及资源回归。没有这些证据，不得通过启用原始事件订阅来扩大已声明能力。
